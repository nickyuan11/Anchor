# 开屏广告 & 摇一摇拦截工具 · 设计文档

Nov 4, 2026 · @Nick yuan

## 1. 项目概述

做一个免 root 的 Android 工具：用无障碍服务自动跳过 App 开屏广告，并抢在"摇一摇"被误触发之前把广告页关掉。第一版自用加朋友间分发，APK 直接安装，不上应用商店。

### 关键决策

| 项目 | 决定 | 理由 |
| --- | --- | --- |
| 平台 | 仅 Android（含鸿蒙 4.x 兼容层） | iOS 不越狱无法操作其他 App；纯血鸿蒙（NEXT / 5.0+）不再运行 Android 应用 |
| 实现方式 | 无障碍服务（AccessibilityService），免 root | 普通用户和两台测试机都无法 root |
| 开发语言 | Kotlin | Android 官方首推，运行效果与 Java 相同，后续维护更好 |
| 界面 | Jetpack Compose | 写界面快，只支持 Kotlin |
| 规则来源 | 内置规则 + 本地 JSON 导入 | 朋友间分发可以开箱即用；MVP 不联网 |
| 分发 | 发 APK（GitHub Release 或直接发文件） | 不上应用商店 |
| 主要适配机型 | 红米 K70（澎湃 OS，Android 14）、华为 Mate40（鸿蒙 4.2） | 两位朋友的测试机 |

### 明确不做

- iOS、纯血鸿蒙
- root / LSPosed 方案（列为远期可选）
- 应用内信息流广告、视频贴片广告（第一版只处理开屏）
- 绕过青少年模式等与广告无关的功能

## 2. 技术原理

核心思路是模拟人手点"跳过"。工具不修改、不拦截其他 App，只在用户授权后替用户完成点击。

### 开屏广告怎么跳过

1. 无障碍服务订阅窗口事件：`TYPE_WINDOW_STATE_CHANGED`（换页面）和 `TYPE_WINDOW_CONTENT_CHANGED`（页面内容变化）。
2. 从事件中拿到当前 App 的包名和 Activity 类名，判断是哪个 App 的哪个页面。
3. 查这个 App 有没有规则。有规则就按规则找；没有规则就走通用兜底（见下）。
4. 在当前窗口的节点树（`rootInActiveWindow`）里找目标节点，按优先级匹配：view id → 文字 → 内容描述（content-description）→ 屏幕位置。
5. 执行点击：节点可点击就用 `performAction(ACTION_CLICK)`；不可点击就向上找可点击的父节点；还不行就用 `dispatchGesture` 在节点中心模拟一次手指点击。
6. 记录日志，并防抖：同一个页面、同一条规则在短时间内只点一次，避免连点。

**通用兜底**：没有专属规则时，查找文字为"跳过""跳过广告""Skip"等的节点。为减少误点，只在 App 刚打开的几秒内生效，并要求节点位于屏幕边角区域、尺寸较小。这个功能用户可以关闭。

**已知难点**：部分广告 SDK 的跳过按钮是自己画的，或者在 WebView 里，节点树里看不到文字。这种情况需要按屏幕位置（百分比坐标）写规则来点。

### 摇一摇怎么应对

免 root 拦不住传感器，所以策略是"比用户手抖更快"：广告页一出现就立刻关掉，摇一摇就没有机会触发。

- **速度优先**：收到换页事件立即处理，不等内容稳定；规则在启动时预先加载到内存，按包名直接查表。
- **事件节流**：页面内容变化事件非常频繁，只对有规则或处于启动窗口期的 App 处理，其余直接丢弃。
- **识别记录**：检测到页面有"摇一摇"等字样时记入日志，方便统计哪些 App 有摇一摇广告、跳过是否及时。
- **远期可选**：做一个 LSPosed 模块，Hook 目标 App 的 `SensorManager.registerListener`，在开屏阶段不给它传感器数据，从根上屏蔽。需要 root，第一版不做。

## 4. 技术栈与项目结构

单模块 Android 项目，MVVM 架构，全部使用 Google 官方主流组件。对你来说 Room 约等于 MyBatis-Plus，Hilt 约等于 Spring 的依赖注入，概念都能对上。

| 层面 | 选型 | 备注 |
| --- | --- | --- |
| 语言 | Kotlin + Coroutines / Flow | 协程处理异步，Flow 让界面自动刷新 |
| 界面 | Jetpack Compose + Material 3 |  |
| 架构 | MVVM（ViewModel + Repository） |  |
| 依赖注入 | Hilt | 类比 Spring 的 @Autowired |
| 本地数据库 | Room | 存跳过记录；类比 MyBatis-Plus |
| 设置存储 | DataStore | 存开关、白名单 |
| JSON 解析 | kotlinx.serialization | 解析规则文件 |
| 构建 | Gradle Kotlin DSL + Version Catalog |  |
| 最低系统 | minSdk 26（Android 8.0） | targetSdk 用 Android Studio 当前稳定版默认值 |

```
app/src/main/
├── assets/rules/builtin.json      # 内置规则
├── res/xml/accessibility_config.xml
└── java/<包名>/
    ├── service/                   # 无障碍服务入口
    │   ├── SkipAccessibilityService.kt
    │   └── ActionExecutor.kt      # 点击、手势
    ├── engine/                    # 规则引擎
    │   ├── RuleMatcher.kt         # 包名/Activity → 规则
    │   ├── NodeFinder.kt          # 节点树查找
    │   ├── FallbackMatcher.kt     # 通用关键词兜底
    │   └── Debouncer.kt           # 防抖
    ├── rule/                      # 规则模型与加载
    │   ├── model/
    │   └── RuleRepository.kt
    ├── snapshot/                  # 页面快照抓取与导出
    ├── data/                      # Room、DataStore
    ├── ui/                        # Compose 页面
    │   ├── home/  guide/  logs/  whitelist/  settings/
    ├── debug/                     # 仅 debug 包：模拟广告测试页
    └── util/                      # 机型判断、跳转系统设置
```

包名待定，建议形如 `com.<你的英文名>.adskip`。

## 5. 核心模块设计

左边一列是一次跳过的主流程，从上往下走；右边是辅助模块。规则引擎不依赖无障碍服务本身，只接收"包名、Activity、节点树"作为输入，这样可以脱离手机写单元测试。

&#91;embedded content: 核心模块 · 一次跳过的数据流\]

- **线程**：无障碍事件回调在主线程，节点查找放到单线程协程调度器执行，既不卡界面，又保证事件按顺序处理。
- **节流**：只处理有规则、或处于启动窗口期的 App 的内容变化事件，其余直接丢弃。
- **防抖**：Debouncer 以"包名 + 规则 id"为键，在 `maxClicks` 和时间窗口内不重复执行。（原设计含 Activity；真机发现 App 打开过程中 Activity 名可能从未知变为具体值，导致同一按钮被点两次，故去掉）
- **快照独立**：快照工具只读页面、不点击，与跳过流程互不影响。

## 6. 规则格式设计

规则是一个 JSON 文件，按 App 分组，每个 App 下有多条规则。内置规则和用户规则格式相同，用户规则按 `id` 覆盖同名内置规则。

```json
{
  "version": 1,
  "apps": [
    {
      "packageName": "com.example.app",
      "name": "示例 App",
      "enabled": true,
      "rules": [
        {
          "id": "splash-skip",
          "type": "splash",
          "activities": ["com.example.app.SplashActivity"],
          "matchWindowMs": 8000,
          "match": [
            { "viewId": "com.example.app:id/skip_btn" },
            { "text": "跳过", "textMatch": "contains" }
          ],
          "action": "click",
          "clickBy": "gesture",
          "maxClicks": 1
        },
        {
          "id": "splash-skip-by-position",
          "type": "splash",
          "activities": ["*"],
          "condition": { "textExists": "摇一摇" },
          "position": { "x": 0.88, "y": 0.06 },
          "action": "tapPosition",
          "maxClicks": 1
        }
      ]
    }
  ]
}
```

| 字段 | 含义 |
| --- | --- |
| `packageName` | 目标 App 包名 |
| `rules[].id` | 规则唯一标识，用户规则以此覆盖内置规则 |
| `type` | 规则类型，MVP 只有 `splash`（开屏），v1.2 加 `popup`（弹窗） |
| `activities` | 生效的页面类名，`*` 表示该 App 所有页面 |
| `matchWindowMs` | App 进入前台后多少毫秒内有效，超时不再匹配，防止误点正常内容 |
| `match` | 节点匹配条件，按数组顺序尝试，命中一个即可；支持 `viewId`、`text`、`desc` |
| `textMatch` | 文字匹配方式：`equals`、`contains`、`regex` |
| `condition` | 可选前置条件，如页面上必须存在某段文字 |
| `position` | 按屏幕百分比坐标点击，用于看不到节点的情况 |
| `action` | `click`（点击节点）、`tapPosition`（点击坐标）、`back`（按返回键） |
| `clickBy` | 可选，仅 `action` 为 `click` 时有效：`node`（让系统直接点控件）、`gesture`（在控件位置模拟手指点击）。不写时先点控件，0.5 秒后按钮仍在则改用手势重试。有的广告只认真实触摸（如腾讯视频），写 `gesture` 可省掉这 0.5 秒 |
| `maxClicks` | 每次进入页面最多执行几次 |

通用兜底不写在规则文件里，而是设置项：关键词列表、生效时长、节点必须位于的屏幕区域。

内置规则的具体内容不在本文档预先编写。等快照工具做好后，由朋友导出真实 App 的页面快照，再据此编写，保证规则准确。

## 7. 国产系统适配与保活

工具好不好用，一半取决于无障碍服务会不会被系统杀掉。App 内能做的是"检测 + 一键跳转 + 说明"，真正的开关需要用户手动打开。

**第一个坑：受限制的设置。** Android 13 起，不是从应用商店安装的 APK，默认不允许开启无障碍服务，开关是灰的。用户需要先到"应用信息"右上角菜单里点"允许受限制的设置"。你们是直接装 APK，所以引导页第一步就要讲这个。

| 系统 | 用户需手动设置 |
| --- | --- |
| 澎湃 OS（红米 K70） | 允许受限制的设置 → 开启无障碍服务 → 自启动：开 → 省电策略：无限制 → 最近任务中下拉锁定本 App |
| 鸿蒙 4.2（Mate40） | 开启无障碍服务 → 应用启动管理改为"手动管理"，允许自启动、关联启动、后台活动 → 电池优化：不允许 |

具体菜单名称可能随系统版本变化，以测试机实际界面为准，引导页文案在 M4 阶段由朋友截图确认。

### App 内实现

- **状态检测**：首页实时显示服务是否在运行，没运行时红色提示并给出"去开启"按钮。
- **一键跳转**：跳转无障碍设置、应用详情、电池优化等页面；针对小米、华为尝试跳转各自的自启动管理页，失败则回退到应用详情页。
- **请求忽略电池优化**：调用系统弹窗，让用户一键同意。
- **机型识别**：根据 `Build.MANUFACTURER` 判断厂商，展示对应的图文引导。

### 无障碍服务配置要点

- `canRetrieveWindowContent="true"`：允许读取页面内容
- `accessibilityFlags` 包含 `flagReportViewIds`（拿到 view id）和 `flagRetrieveInteractiveWindows`
- 监听所有 App，不在配置里写死包名，过滤逻辑放在代码中
- 服务描述文案写清楚用途，用户开启时会看到

## 8. 开发里程碑与测试计划

分 6 个里程碑，每个都有可验证的完成标准；做完一个，确认通过再进入下一个。前三个里程碑可以完全在模拟器上完成，不依赖朋友。

1. **M0 环境准备**：安装 Android Studio，创建模拟器，新建 Compose 空项目并跑起来。
   - 完成标准：模拟器上显示 Hello 页面。
2. **M1 模拟广告测试页**：在 debug 包里做一个假的开屏广告页，带倒计时、"跳过"按钮，并用加速度传感器模拟摇一摇跳转。
   - 完成标准：手动打开测试页，摇一摇会跳走，点跳过能进入主页。模拟器的虚拟传感器可以模拟晃动。
3. **M2 最小跳过能力**：无障碍服务 + 通用关键词兜底 + 跳过记录页。
   - 完成标准：开启服务后，打开测试页能被自动跳过，记录页有对应日志，跳过发生在摇一摇触发之前。
4. **M3 页面快照工具**：悬浮按钮抓取当前页面结构并导出 zip。
   - 完成标准：发 APK 给朋友，朋友能导出真实 App 开屏广告的快照并发给你。
5. **M4 规则引擎 + 内置规则 + 引导保活**：实现第 6 节的规则格式，根据快照写内置规则；完成开启引导和机型保活引导。
   - 完成标准：两台测试机上，内置规则覆盖的 App 都能稳定跳过；锁屏放置一晚后服务仍在运行。
6. **M5 打包 v1.0**：配置 release 签名，生成正式 APK，写一份简单的安装说明。

### 测试安排

| 测试项 | 设备 | 方法 | 通过标准 |
| --- | --- | --- | --- |
| 跳过逻辑 | 模拟器 | 模拟广告测试页 | 每次都能跳过，不重复点击 |
| 真实 App 跳过 | 红米 K70、Mate40 | 朋友日常使用一周，导出记录和失败快照 | 规则覆盖的 App 基本不再看到开屏广告 |
| 误点检查 | 红米 K70、Mate40 | 日常使用中留意是否点错正常内容 | 无误点反馈 |
| 保活 | 红米 K70、Mate40 | 按引导设置后，锁屏放置过夜 | 第二天服务仍在运行 |
| 安装与开启流程 | 两台测试机 | 让朋友只看引导页自己完成设置 | 不需要你远程指导 |

**设备建议**：如果预算允许，买一台二手安卓机放在手边，M3 之后的调试效率会高很多。
